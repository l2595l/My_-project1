## 0. 结论摘要

1. **三个词条全部改「谁可以被攻击」（§6.2-6 的预警正确）**：烟幕/守护改 `CanAttackTarget` 的**合法性**；
   伏击不改合法性、改**结算顺序**（先制伤害）——三者与任务 D 重构的射程/拦截判定**同处一个函数链**，
   但**判定点各自独立**（烟幕最前、守护最后、伏击在结算段），可以干净归因。
2. **一个漂亮的收口发现（伏击）**：伏击的"先制伤害"走 **`CounterDamage` 同一通道**（不新建数值出口），
   于是三条官方细则**零特殊代码自动成立**：
   ① "让轰炸机或炮兵首先攻击也可以消除伏击效果"——轰/炮的 `CounterDamage` 本来就是 0；
   ② "冲击无视伏击"——冲击条款在 `CounterDamage` 最前，先制伤害直接归 0；
   ③ "重甲减免对战伤害"——先制伤害照走重甲收尾。
3. **三个词条的"一次性状态"三种形态**（防记混，见 §1.4 对照表）：
   冲击=不恢复（第一批）、**烟幕=失去后不恢复**、**伏击=每回合恢复**（唯一会"回来"的）。
4. **卡池挂载需要一次原则拍板**：本批推荐**解禁"一卡双词条"（仅 1 张：装甲车 +守护）**——
   理由：全卡池 10 张单位卡在第二批后**全部带词条**（无"干净卡"可用），而"守护"的天然载体
   （机枪阵地/装甲车/重坦）都已在第一批占位；若不破例，只能把伏击压给两张 1 费卡（1/1 先制 1 伤
   ≈ 200 局里测不出来）。方案 A（零双词条）作为备选一并列出，**由用户拍板**。
5. **落地前第一小步 = 拆自检文件**（`KardsLikeSelfCheck.cs` 已 1775 行，超 1100 阈值）。
6. **AI 预计零代码改动**（与任务 4 不同——本批没有"部署即时性"类的玩法变化；烟幕/守护走合法性自动被 AI 遵守，
   伏击的"会死"判定已由现有 `dies = CounterDamage(...)` 覆盖）——落地时逐点核对。

## 1. 官方原文核实（按项目纪律：先 WebSearch 核原文，不凭记忆）

### 1.1 三词条定义（多来源交叉；新增"Kards 官方帮助中心"来源）

| 词条 | 官方定义（来源） | 本作现状 |
|---|---|---|
| **烟幕** Smokescreen | 「单位在进行过移动或攻击之前，无法被其他单位攻击，但仍会受到触发效果和指令的伤害」（官方 how-to-play / 维基镜像）；「这张单位**不能**被其他单位攻击」（英文官方：*This unit cannot be attacked by other units until it has moved or attacked on its own*） | ❌ 未实现 |
| **守护** Guard | 「**相邻**单位无法被轰炸机和火炮之外的单位攻击，也可守护**总部**」（官方 how-to-play / 维基镜像）；**官方帮助中心**（`support.kards.com` 条目）：「Units adjacent to a guard unit cannot be attacked **except by bombers and artillery**……**only cards adjacent to** the guard unit will receive the protection……the **headquarter can be guarded** as well」 | ❌ 未实现 |
| **伏击** Ambush | 「此单位**每回合第一次**受到攻击时，会**首先**造成对战伤害。**若将攻击的单位消灭，则不受到对战伤害**」（维基镜像）；Fandom：「首次受到攻击后消失……**会在单位所有者的下个回合开始时重新添加**」 | ❌ 未实现 |

### 1.2 细则清单（9 条，全部有原文出处 —— 落地时逐条对照）

1. **烟幕·范围**：不可被**任何单位**攻击（**无例外名单**——轰炸机/火炮/战斗机一样打不了；对照：守护有例外名单）。
2. **烟幕·穿透**：**指令与卡效果不受影响**（官方原文"仍会受到触发效果和指令的伤害"）。本作：指令卡走
   `CanTargetUnit`/`PlayCard` 路径，**不经过** `CanAttackTarget` ⇒ 自动成立（落地时核对这两个函数别误加烟幕判定）。
3. **烟幕·失去**：「**移动或攻击过之后**」立即失去（没有 HQ 例外条款——攻击 HQ 也算"攻击过"）。
4. **烟幕·禁止组合**：「守护单位和位于**前线的单位**以及**战斗机**不能具有烟幕」（Fandom 中文细则）；
   其中"前线"是**运行时行为**（移动上前线时烟幕已因"移动"而失去——自动成立）；
   "守护/战斗机"两条是**数据合法性**（由 `ValidatePanelBudget` 校验）。
5. **守护·相邻**：只有**相邻**单位（与 HQ）受保护——「only cards **adjacent to** the guard unit will receive the protection」；
   本作已拍板：**同线索引 ±1、HQ 固定索引 0**（设计文档 §14.7①）。
6. **守护·例外名单**：**只有轰炸机和火炮**（「except by bombers and artillery」）——**战斗机不在名单**
   （Kards 官方名单里只有这两类；本作"战斗机越线"是自创能力包，**默认不叠加**"无视守护"——子问题，见 §4.3）。
7. **守护·自身不受保护**：「守护单位无法获得被守护效果，因此不能让相邻的守护单位相互守护」（Fandom）——
   守护单位自己是**完全可被攻击**的普通合法目标。
8. **守护·解除方式**（官方帮助中心）：摧毁守护单位本身 / **发指令卡**（Order）/ 其他卡效果——
   本作语义：① 守护单位死亡 ⇒ 保护自动消失（判定读"存活"）；② 指令穿透（同烟幕·穿透，自动）；
   ③ 本作当前没有"移除词条"类效果（登记）。
9. **伏击·先制结算**：「每回合第一次受到攻击时，会**首先**造成对战伤害。**若将攻击的单位消灭，则不受到对战伤害**」——
   即：伏击方先打；若攻击者被这一击**消灭**，攻击者的伤害**不发生**（伏击方不受伤）。
   还有两条联动（第一批已核实）：**"使用冲击单位攻击伏击单位，同样不会受到反击伤害"**、
   **"让轰炸机或炮兵首先攻击也可以消除伏击效果"**。

### 1.3 官方帮助中心的额外收获（本轮新增来源）

- 守护是**被动能力**（passive ability）、**自动生效**（不需要主动开启）；
- "移除守护保护"的完整清单：摧毁守护单位 / **指令**（原文举例 Overwhelming Force、Breakthrough）/ 其他卡效果
  ⇒ 印证 §1.2-8 的本作语义（保护只挡**单位攻击**）；
- 识别方式（卡面符号）——本作词条显示走卡面 `Text`（第一批既定最小方案，延续）。

### 1.4 与第一批的对称性检查（防记混——三种"一次性状态"三种形态）

| 词条 | 实例状态字段 | 触发/失去条件 | **恢复** |
|---|---|---|---|
| 冲击（第一批） | `HasShock` | 只要发动攻击（含打 HQ） | ❌ **不恢复**（一生一次） |

## 2. 规则复述（翻成本作口径）

### 2.1 烟幕 Smokescreen

- **语义**：拥有烟幕的单位**不能被任何敌方单位攻击**（所有兵种一视同仁）。
- **穿透**：指令卡与卡效果**不受影响**（精准打击 / 炮火覆盖照常可打——本作自动成立）。
- **失去**：该单位**攻击**（含打 HQ）**或移动**后立即失去；**不恢复**。
- **自动边界**："前线单位不能有烟幕"⇒ 移动上前线时已因"移动"失去——自动成立；
  "守护/战斗机不能有烟幕"⇒ 数据校验禁止（本批挂载不涉及，防未来）。
- **实现**：`CanAttackTarget` 加**最前**判定；消耗点**两处**：`AttackWithUnit`（攻击后）+ `MoveUnit`（移动后）。

### 2.2 守护 Guard

- **语义**：守护单位**保护相邻目标**（同线索引 ±1 的单位与 HQ）——被守护目标**只能被轰炸机和火炮攻击**
  （名单待拍板：战斗机是否加入，默认不加入）。
- **自身**：守护单位**不被保护**（两个相邻守护单位互相都不受护）。
- **解除**：守护单位**死亡** ⇒ 保护立即消失（实时判定，零清理代码）；**指令穿透**（自动）。
- **实现**：`CanAttackTarget` 加**最后**判定（`IsGuardedTarget`：查邻居模式复用 `IsBombingIntercepted` 的线查找）。

### 2.3 伏击 Ambush

- **语义**：伏击单位**每回合首次被攻击**时，**先制**造成它的反击伤害（`CounterDamage` 通道）；
  **若攻击者被这一击消灭 ⇒ 攻击者的伤害不发生**（伏击方不受伤）。
- **动作照常消耗**：攻击指令已下达——**攻击方的行动与费用照常扣除**（本作口径：攻击"发生"但伤害不发生；
  官方未细化，此为最自然语义，登记在案）。
- **消耗**：被攻击即消耗（"首次被攻击后消失"；攻击被**拒绝**不算）；**回合开始恢复**（所有者侧）。
- **三条自动成立的联动**（零特殊代码，见 §0-2）：轰/炮拆伏击（先制=0）、冲击无视伏击（先制=0）、重甲减先制。
- **实现**：`AttackWithUnit` 结算段（先制顺序 + 击杀则伤害不发生）；状态恢复在 `ResetUnitStates`。

## 3. 九问九答

### Q1 数据怎么存？

**三词条全部是布尔型 ⇒ 只扩枚举位，不加新字段**：

```csharp
[Flags]
public enum Keyword
{
    None   = 0,
    Blitz  = 1 << 0,
    Shock  = 1 << 1,
    Smoke  = 1 << 2,   // [任务5] 烟幕
    Guard  = 1 << 3,   // [任务5] 守护
    Ambush = 1 << 4,   // [任务5] 伏击
}
```

- `AllowedKeywords` 常量同步加三位（"未实现位被填 ⇒ 报错"的防护继续有效）；
- `UnitInstance` 加两个一次性状态字段：`HasSmoke`、`HasAmbush`（构造从 Def 初始化——**绝不落 Def**、
  绝不写回共享卡定义，与 `HasShock` 同款纪律）；
- `ValidatePanelBudget` 加两条组合合法性：**守护单位不能有烟幕**、**战斗机不能有烟幕**（§1.2-4）。

### Q2 烟幕的判定点与消耗点？

- **判定点唯一**：`CanAttackTarget` 的**第一行**（在射程/拦截/守护之前）——
  "烟幕不可被任何单位攻击"是**绝对**条款（无例外名单），先报它语义最准。
- **消耗点两处、缺一不可**：
  - `AttackWithUnit` 成功路径：`if (attacker.HasSmoke) attacker.HasSmoke = false;`（攻击后失去，含打 HQ）；
  - `MoveUnit` 成功路径：`if (u.HasSmoke) u.HasSmoke = false;`（移动后失去）。
- ⚠️ **指令路径绝不能加烟幕判定**（`CanTargetUnit`/`PlayCard` 保持原样）——否则指令也打不了烟幕单位，
  违反官方"仍会受到指令的伤害"（§1.2-2）。

### Q3 守护的判定怎么做？（邻居查找 + 例外名单 + 三个边界）

```csharp
// CanAttackTarget 末尾（拦截判定之后，顺序见 Q6）：
if (IsGuardedTarget(target, attacker)) { reason = "目标受相邻守护单位保护（只有轰炸机或火炮能攻击它）"; return false; }

private bool IsGuardedTarget(UnitInstance target, UnitInstance attacker)
{
    if (target.Def.HasKeyword(Keyword.Guard)) return false;              // ① 守护单位自身不受保护
    if (attacker.Def.UnitKind == UnitType.Bomber
        || attacker.Def.UnitKind == UnitType.Artillery) return false;    // ② 例外名单（待拍板：+战斗机?）
    List<UnitInstance> line = target.Line == Line.Front
        ? State.Frontline : State.Players[target.OwnerIndex].SupportLine;  // ③ 复用 IsBombingIntercepted 的线查找
    int idx = line.IndexOf(target);
    if (idx < 0) return false;
    if (idx - 1 >= 0 && IsGuardUnit(line[idx - 1])) return true;           // ④ 相邻 = 索引 ±1（已拍板）
    if (idx + 1 < line.Count && IsGuardUnit(line[idx + 1])) return true;
    return false;
}
private static bool IsGuardUnit(UnitInstance u)
{
    return u != null && u.IsAlive && u.Def.HasKeyword(Keyword.Guard);      // ⑤ 死亡即失效（实时）
}
```

三个边界：**HQ 可被守护**（HQ 在支援线索引 0，邻居=索引 1 的守护——自动成立）；
**前线守护**保护前线邻居（同一线查找逻辑）；**守护单位自身**永远是完全合法的攻击目标（§1.2-7）。

### Q4 伏击的结算怎么改？（先制模型 + 三条自动联动）

`AttackWithUnit` 结算段改为：

```csharp
int damageToTarget  = UnitAttackDamage(attacker, target);
int damageToAttacker = CounterDamage(attacker, target);

bool ambushTriggered = target.HasAmbush;          // 伏击：本回合尚未触发
if (ambushTriggered) target.HasAmbush = false;    // 被攻击即消耗

attacker.Health -= damageToAttacker;              // 伏击时这一笔变成"先制"（顺序提前）
if (!ambushTriggered || attacker.Health > 0)      // 伏击先制击杀攻击者 ⇒ 攻击者的伤害不发生
{
    target.Health -= damageToTarget;
}
SpendAttack(attacker);
if (attacker.HasSmoke) attacker.HasSmoke = false; // [任务5] 烟幕：攻击后失去
if (attacker.HasShock) attacker.HasShock = false; // [任务4] 冲击：只要攻击就消耗
```

- **为什么走 `CounterDamage` 通道**：伏击先制伤 = "目标对攻击者的反击"（同一份数值）——
  轰/炮拆伏击（0）、冲击无视伏击（0）、重甲减先制——**全部零特殊代码**（§0-2）；
- **无伏击时行为与现状逐位一致**（两行扣血换个写法，顺序对独立对象无影响——对照轮会验证）；
- **日志文案**（落地时）：伏击场景输出"（伏击先制）"后缀 + 击杀场景输出"XX 阵亡——伤害未发生"，
  非伏击路径字面不变（保持第 3 项"逐日志文本一致"的可比性）。

### Q5 伏击的状态与恢复点在哪？

- `HasAmbush`（实例字段，构造 `= def.HasKeyword(Ambush)`）；
- **消耗**：`AttackWithUnit` 里 `ambushTriggered` 判定后置 false（**被攻击即消耗**——攻击被拒绝不会走到这里 ✓）；
- **恢复**：`ResetUnitStates`（该单位所有者的回合开始）：

```csharp
if (unit.Def.HasKeyword(Keyword.Ambush)) unit.HasAmbush = true;   // 伏击：每回合恢复（官方）
```

  ——与 `HasShock`/`HasSmoke`（不恢复、回合重置**不管**）刻意不同——三种形态对照表见 §1.4。

### Q6 `CanAttackTarget` 的判定顺序怎么定死？

现状链：`null/存活/己方 → 射程分岔 → 拦截`。本批插入后**定死**为：

```
① 烟幕（绝对条款，最前）
② 射程分岔（任务 D）
③ 战斗机拦截（任务 D）
④ 守护（例外名单条款，最后）
```

- 顺序只影响**拒绝 reason 的优先级**（合法性结果一致——每层都返回 false）；
- ④ 放最后：它判定成本最高（查邻居）且"最弱"（有豁免名单）——先报前面更根本的拒绝理由；
- 一个盘面覆盖多个条款时（如"被守护且有烟幕"）：报①——语义最准（烟幕连轰/炮都挡，是更强的保护）。

### Q7 AI 需要改吗？（任务 D 教训的反面——预计零改动）

逐点核对：

| 点 | 结论 |
|---|---|
| 烟幕/守护 | AI 只用 `CanAttackTarget` 选目标 ⇒ **自动跳过**被保护目标（不能打就换个目标）；**零改动** |
| 伏击·"会死吗" | AI 现有 `dies = GameEngine.CounterDamage(atk, tgt) >= atk.Health` —— 先制伤害同通道 ⇒ **自动正确**（AI 会规避伏击自杀交换） |
| 伏击·"第二轮允许死亡交换" | `requireNoLoss=false` 的轮次 AI 会接受"能击杀的死亡交换"——伏击照常触发（这是想要的行为） |
| 打 HQ 路径 | `CanAttackHq` → `CanAttackTarget` 一行收口 ⇒ 守护 HQ/烟幕（HQ 无词条）自动生效；**零改动** |
| 目标选择评分 | 不感知新词条（近似即可）——被守护目标进不了候选集，评分自然落在合法目标上；**零改动** |

⇒ **本批 AI 零改动**（与任务 4 的"2 处"形成对照——因为本批不引入新的"即时性"玩法）。

### 4.1 现实约束（为什么必须拍板）

- 全卡池 10 张单位卡：第一批已挂 **6 张**（闪击×2 / 冲击×2 / 重甲×2）；

- **守护的天然载体**（机枪阵地/装甲车/重坦）**全部已在第一批占位** ⇒ 不破例就得把守护压给榴弹炮（风味凑合）。

### 4.2 方案 B（**推荐**）：解禁"一卡双词条"×1

| 卡 | 费 | 现面板（任务4后） | 新词条 | **折让后** | 理由 |
|---|---|---|---|---|---|
| 侦察兵 | 1 | 1/2 | **烟幕** | **1/1** | 潜伏侦察——风味最佳；1 费卡终于挂词条（1/1 弱，如实登记） |

| 榴弹炮 | 6 | 6/5 | **伏击** | **6/4** | 隐蔽炮位——先制 6 伤（200 局里**看得见**的伏击强度，测试有效） |

  `4/5 − 2 ⇒ 3/4（推荐，保血——守护卡要活得久）` 或 `4/3（备选，保反击威胁）`；
- 收益：三词条载体全部"会被玩到"（4/5 费常客），伏击先制 6 在数据里可见；
- 代价：① 破"一卡一词条"（仅此一张，登记）；② 装甲车 3/4+重甲1+守护 的强度需盯（200 局 + 后续采样）。

### 4.3 方案 A（**备选**）：零双词条（4 张全用未挂卡）

|---|---|---|---|---|

### 4.4 子问题（需拍板）：**守护的例外名单是否含"战斗机"？**

- 官方名单**只有轰炸机和火炮**（多来源一致）；本作"战斗机"是**自创的越线兵种**（Kards 原版不在守护语境里出现）。

  且守护的解法（轰/炮）在卡池里各有 1 张，够用。
- 备选：战斗机也算例外（"越线兵种都无视守护"的对称美学）——若你偏好这个，说一声（改一行）。
