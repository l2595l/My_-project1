## 1. 规则复述

### 1.1 Kards 口径（三来源一致，已在设计文档 §14.5 核实）

- 百度百科 KARDS「单位类型」：「坦克可以在同一回合中移动并攻击，**顺序不限**。坦克只能攻击相邻战线中的敌人。」
- LevelWinner 指南：*"Tank … can both move and attack on the same turn. Do note that you must **pay Kredits for both** of these actions!"* 及 *"only tanks can do both in the same turn"*。
- Fandom（Blitz 条）：*"Units with Blitz cannot move and attack on the turn they come into play **unless they are a Tank**."*

### 1.2 本作现状与目标

| | 现状 | 目标 |
|---|---|---|
| 行动经济 | 全兵种**移动与攻击二选一**（`HasOperatedThisTurn` 单布尔，`CanUnitAct` 收口） | **仅坦克**豁免：移动一次**且**攻击一次（各一次，不是各无限次） |
| 射程 | 坦克 = 地面部队：支援线只能打敌方前线；前线能打敌方前线/支援线/HQ | **不变**（本任务不碰射程与拦截） |
| 行动费 | 每次行动按部署费用分档扣资源（1/2/3），唯一出口 `SpendAction` | 坦克**两个动作各扣一次**（同价格、各付一次） |
| 部署失调 | 部署当回合既不能移也不能攻 | **不变**（坦克不豁免） |

### 1.3 三条已核实口径（实现时不许走样）

1. **不豁免部署失调** —— 坦克部署当回合仍不能行动，除非它有「闪击」（任务 4 落地后）⇒ **「闪击 × 坦克」是唯一的"登场即可移动 + 攻击"组合**。
2. **两次行动各付一次行动费**，顺序不限。
3. **顺序影响合法性**："先攻击再移动"时，攻击目标按**移动前**的位置算；"先移动再攻击"按移动后算 ⇒ 实现**不能**把两个动作当无序处理。

> ⚠️ 与 §7.1 旧注的关系：§7.1 里「② 移动与攻击二选一，坦克例外」描述的是 Kards，**本作当前未实现**（§14.5 登记）。本任务把这条例外落地后，那条注记升级为"已实现"。

## 2. 九问九答

### Q1 部署失调是否豁免？对「闪击 × 坦克」意味着什么？

**不豁免（确认）**。坦克只是"每回合的行动上限"从 1 变为 2，**不改变"部署当回合不能行动"**。

- 对节奏的含义：普通单位走到敌方 HQ 需要**三个己方回合**（部署 → 移动上前线 → 攻击）；坦克变成**两个**（部署 → [移 + 攻] 同回合）。
- 对「闪击 × 坦克」的含义：闪击豁免"部署当回合"限制，于是**闪击坦克可以在登场当回合直接完成"移动 + 攻击"两步**——这是全游戏唯一的"登场即两动"组合（任务 4 落地后生效；本任务的实现**已经天然支持**：闪击只把 `DeployedThisTurn` 置 false，后面两条豁免都由本任务的改动负责）。

### Q2 两次行动各扣一次行动费吗？扣费点在哪、失败如何回滚？

**是，各扣一次（确认）**。

- 扣费唯一出口：`SpendAction(u)`（`GameEngine.Play.cs:225` 附近）——现在是"置 `HasOperatedThisTurn` + 扣 `Resources -= ActionCostOf(u.Def)`"一行函数；本任务把它**拆成 `SpendMove` / `SpendAttack`**（各自置对应 flag + 扣一次费），保持"只有一个出口"的性质。
- **失败回滚：不存在需要回滚的场景**。所有校验（含资源检查）都在动作执行**之前**（`CanUnitAct` 系），扣费只在成功路径的**末端**。任何一步失败 = 提前 return，一分钱不扣。
- ⚠️ 一个**不是**错误的场景：坦克第一个动作后资源不够第二个 ⇒ 第二个动作被拒（"资源不足"），第一个动作保持生效。"只做一样"是"顺序不限"的合法选择，**不需要原子化两笔支付**。

### Q3 "顺序不限"的实现含义？现在的 MoveUnit / AttackWithUnit 是否天然支持？

**天然支持，不需要显式排序逻辑（确认）**。理由：

- 两个入口各自独立走"校验 → 执行 → 扣费"三段，**从不预计算、不缓存**；`CanAttackTarget` 永远读**调用当下**的 `attacker.Line`。
- 于是："先攻击再移动"时，攻击发生在 `Line == Support` → 只能打敌方前线（按移动前位置）✓；"先移动再攻击"时，攻击发生在 `Line == Front` → 能打敌方前线/支援线/HQ ✓。**口径自动成立，一行排序代码都不需要。**
- 唯一前提：把"已行动"的校验**放行**（拆 flag，见 Q4）——否则第二个动作会被 `CanUnitAct` 挡掉。
- 具体例子（会写进自检第 11 项）：坦克在支援线先攻时 `CanAttackHq == false`；移动后再查 `CanAttackHq == true`。

### Q4 字段改造方案？波及哪些函数？

**方案：拆两个布尔**（采纳提示词倾向）。

```
UnitInstance:
  HasMovedThisTurn     // 本回合是否已移动
  HasAttackedThisTurn  // 本回合是否已攻击
（删除 HasOperatedThisTurn）
```

判定表（"还能不能做这个动作"）：

| 单位 | CanUnitMove 的"已行动"检查 | CanUnitAttack 的"已行动"检查 |
|---|---|---|
| **坦克** | `!HasMovedThisTurn`（已攻过也放行） | `!HasAttackedThisTurn`（已移过也放行） |
| **非坦克** | `!HasMovedThisTurn && !HasAttackedThisTurn`（任一为 true 即拒绝） | 同左 |

- "非坦克两者不能同时为 true"**不需要额外的字段约束**——它是上表判定的自然推论（动作受理时先检查、后置位）。
- `CanUnitAct` 语义从"整体一次机会"改为"**还有任何剩余动作**"：坦克 `!(Moved && Attacked)`、非坦克 `!(Moved || Attacked)`。`HasAttackTarget` 等复用它的地方自动适配。
- **新增一个只读辅助（单一出口）**：供 View 显示 / AI 预算统一判"本回合已无行动空间"。放 `GameEngine`（与 `ActionCostOf` 并列的静态），命名如 `HasNoActionLeft(UnitInstance)`——**禁止 View / AI 自己写兵种 if**（"规则在引擎"铁律；否则又是两套语义）。

### Q5 与「奋战」的关系（坦克 + 奋战 = ？）

**本轮不定义（明确声明）**。

- 奋战（每回合攻击两次）属任务 6，而且设计文档 §14.7 ② 已登记："`HasOperatedThisTurn` 是全兵种共用的一个布尔值，坦克规则与奋战词条**都要改它** ⇒ 两者不能同一轮做"——本任务先拆成两个 **bool**；奋战轮若需要"攻击两次"，把 `HasAttackedThisTurn` 升级为计数器（或引入独立字段），**本轮不预先设计**（避免为不存在的机制写结构）。
- "移 1 + 攻 2"的叠加口径留到奋战轮拍板；本轮实现**不阻止**未来叠加（两个 flag 结构天然可扩展）。

### Q6 GreedyAI 要改哪几处？出手顺序应当是"先移动后攻击"还是"先攻击后移动"？

**改动 = 2 处**：

1. `ReserveForActions`（"留钱给行动"的保守下界）：`HasOperatedThisTurn` 的筛选改读新判定。细化：**还有两个动作的坦克按 2 笔预留**（它真会花两次），其余按 1 笔——否则预留不足会让 AI 的坦克打完第一下没钱打第二下。
2. **新增"坦克冲锋收尾"小段**（见下）——这是"新机制在 AI 里真正上线"的落点，也是本轮唯一的新 AI 行为。

**出手顺序结论：保持"先攻击、后移动"（不改变全局顺序）**。理由：

- **全局顺序不能动**：现有注释已论证——若先移动，一个 6 费单位的 3 点行动费会先把资源花光，导致"已站在前线、本该打 HQ 的单位"整回合动不了（这是第一版 200 局 L1=0 的直接原因）。普通单位依赖这个顺序。
- **对坦克，"先攻后移"有强组合**："先攻击（击杀挡路的敌前线单位）→ 再移动（占领前线）"——反过来"移入"会被"敌占前线"直接拒绝。这是坦克登场回合后最常见的强势线。
- **"移后本回合不再攻击"的代价可控**：坦克上前线后下回合即可打脸（比普通单位快一整轮）。且本任务给 AI 补一段"冲锋收尾"让"移+打脸"也上线（见下）。

**附注（顺带修复）**：`GamePresenter.Feedback.cs` 的攻击动画判据现在是"`已行动` false→true **且不是移动**"——拆 flag 后直接改读 `HasAttackedThisTurn` false→true，**比现在更精确**，顺带把登记过的"额外攻击会漏播（只认 false→true）"隐患里最容易踩的一半消掉（坦克"移+攻"两步会分别触发移动 / 攻击动画，不会再互相遮蔽）。

**新增"坦克冲锋收尾"的设计**（建议项，见 §3.1）：在 `MovePhase` 之后加一小段——"本回合新移上前线的坦克，若还能攻击（`!HasAttackedThisTurn`），尝试打 HQ"。因为 `MovePhase` 每回合最多移动 1 个单位，这段每回合最多触发 1 次；旧规则下永不触发（坦克移后不能攻）⇒ **反向对照轮是安全的**（见 §4.5）。若不加这段，AI 的坦克只发挥"攻+移"防御性一半，"移+打脸"进攻性打法缺失，200 局测不到坦克冲锋的价值。

### Q7 200 局会大面积还是局部变化？理由？

**大面积（预期）**。理由：这不是"某张卡变强"，而是**全兵种的行动经济模型**被改掉，且坦克直接受益：

- 坦克 2 张（装甲车 4/5、重型坦克 7/6）每回合行动上限翻倍（1 → 2）⇒ 卡池强度结构变化；
- 节奏侧：坦克省掉"站位回合" ⇒ 前线占领与打脸都可能加速；
- 先手偏差：**方向不猜**（"坦克让先手更快打脸"与"后手有更多资源还手"是两股相反的力——任务 D 已经被"猜错方向"上过一课，以实测为准）。

**要吸取的教训（任务 A / 任务 D 连续两次"预测局部、实际大面积"）**：本轮**从机制上就必然大面积**——不再做"某类局逐位不变"的预测，直接按"全部数字会变"准备，用反向对照轮做唯一归因。

**可验证的观察点（跑完对照）**：① 平均 HalfTurn 是否再降（打脸提速）；② 打脸击破率是否维持 100%；③ 先手偏差相对 13.0 的摆动量级（记录，不预测方向）。

### Q8 自检新增第几项？断言清单？

**第 5 项适配 + 新增第 11 项**（自检 10 → 11 项）：

- **第 5 项（适配）**：它测"部署失调 + 每回合一次行动"，用例单位来自种子随机 → **种子筛选加"非坦克"条件**（找一个开局手上是可打出的**非坦克**单位卡的种子），标题与文字标注"（非坦克）"。语义保持"二选一"，坦克的例外由第 11 项覆盖。
- **第 11 项「坦克移动 + 攻击」（新增，手工摆盘 + 硬编码期望）**：
  1. 坦克部署当回合：不能移动、不能攻击（**部署失调不豁免**）；
  2. 下回合：移动成功（扣 1 笔行动费）→ **移动后 `CanUnitAttack == true`**（关键断言——旧规则此处应为 false）→ 攻击成功（扣第 2 笔）→ 资源总差 = **2 × 行动费**；
  3. 两个动作后再查：`CanUnitMove == false` **且** `CanUnitAttack == false`（坦克是"各一次"，不是无限）；
  4. 对偶断言：非坦克"移动后不能攻击"仍成立（一条断言内嵌，防止通用逻辑被改坏）；
  5. 顺序不限：第二辆坦克"先攻击（在支援线 → 只能打敌方前线）→ 再移动"成功；且**先攻时 `CanAttackHq == false`、移动后 `CanAttackHq == true`**（"顺序影响合法性"的直接证据）；
  6. 资源不足：坦克移动后资源调到差额不足 → `CanUnitAttack == false`（原因含"资源不足"），且**未扣钱**；
  7. ⚠️ **「闪击坦克登场即可移+攻」留桩**——它依赖任务 4 的闪击字段，**在任务 4 落地时补进断言**（本项先注释占位，不允许含糊成已测）。
- 总数文案同步：菜单/报告"10 项 → 11 项"；报告头"覆盖"行加"坦克移动+攻击"。

## 3. 确认项（等用户点头）

### 3.1 建议采纳：AI 的方案（需确认）

1. 出手顺序**保持"先攻击、后移动"**（理由见 Q6）；
2. **新增"坦克冲锋收尾"小段**（MovePhase 后：新移上前线的坦克若还能攻击 → 打 HQ）——建议加，理由：不加则"移+打脸"打法在 200 局中缺位，新机制只上线一半。

### 3.2 知悉项：View 状态显示的最小方案

- "已行动"压暗 / 状态文字的判定改为**引擎辅助**（`!HasNoActionLeft` 一类）；**坦克"部分完成"（移动未攻击 / 攻击未移动）时不显示特别文案**（不新增"可再动"提示——最小改动；若试玩觉得困惑，另开一小轮）。
- 攻击动画判据升级（`HasAttackedThisTurn` false→true）——自动更精确，无额外成本。

### 3.3 知悉项：200 局预期与对照轮方案

- 预期**大面积变化**、方向不猜（见 Q7）；
- **反向对照轮**：临时把"坦克豁免"关掉（让坦克走普通单位判定）⇒ 应与任务 2 基线**逐位一致**（拆 flag 本身不改变行为时即是）；跑完恢复。
