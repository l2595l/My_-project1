## 2. 规则复述（翻成本作口径）

### 2.1 闪击 Blitz

- **语义**：这张单位卡部署时**跳过"部署失调"**——登场当回合即可行动。
- **行动的额度完全由行动经济决定**（不新增第二条规则）：
  - 闪击 + 非坦克 ⇒ 登场当回合 **移动或攻击，二选一**；
  - 闪击 + 坦克 ⇒ 登场当回合 **移动且攻击**（各一次，顺序不限）；
  - 闪击**不豁免**行动费的扣费（行动照付，与平时一致）。
- **实现**：`unit.DeployedThisTurn = !card.HasKeyword(Keyword.Blitz);`（部署点唯一，`Play.cs:138`）。
- ⚠️ 「视作坦克」「能在同一回合中移动并攻击」的特例卡**本作不做**（官方原文里的例外条款，登记不实现）。

### 2.2 重甲(X) Heavy Armor

- **语义**：拥有重甲 X 的单位，**受到的"单位攻击"伤害减少 X**（下限 0——不能倒吸）。
- **作用范围（两个方向、两类通道）**：
  | 通道 | 是否减免 | 原因 |
  |---|---|---|
  | 被敌方单位**主动攻击**时挨的伤害 | ✅ 减 | 官方"对战伤害" = 单位攻击造成的伤害 |
  | 自己主动攻击时**挨到的反击**伤害 | ✅ 减 | 同上（反击也是单位攻击） |
  | 指令卡伤害（精准打击 / 炮火覆盖） | ❌ 不减 | 官方原文明确排除 |
  | 疲劳伤害（`Turn.cs` 的 `DamageUnit`） | ❌ 不减 | 非单位攻击（且 HQ 无词条，路径上永不触发） |
- **数值**：X ∈ {1, 2, 3}，**单卡上限 3**（数据校验保证）；单位越打越少血时重甲值不变（无动态效果）。
- **实现**：`UnitAttackDamage(attacker, target)`（主动侧，减 **target** 的重甲） +
  `CounterDamage` 收尾（反击侧，减 **attacker** 的重甲）——**这两个函数合起来就是"重甲"的全部**，
  任何第三个减伤点都是 bug。

### 2.3 冲击 Shock

- **语义**：拥有冲击的单位**首次主动攻击"单位"**时，**被攻击单位不造成任何反击伤害**（本次反击 = 0）；
  **随后立刻失去冲击**（一次性，不恢复）。
- **消耗判定**（三条，全部落官方原文）：
  1. 主动攻击**任何单位** ⇒ 消耗（哪怕对方本来就不反击：轰炸机 / 自己也是火炮——"攻击单位后移除"是字面规则）；
  2. 攻击 **HQ** ⇒ **也消耗**（本作拍板简化、不采用官方"打 HQ 不移除"的细则——见 §4.2）；
  3. 攻击**被拒绝**（校验失败）⇒ 不算攻击，不消耗。
- **交互边界**（本次明确，写进实现）：
  - 冲击 × 火炮免反击：火炮**本来**免反击；若给它冲击（本卡池没有这种卡，仅自检夹具验证"无异常"），
    攻击单位后冲击**照常消耗**（字面规则），反击照常为 0——不产生两套语义（都走 `CounterDamage`）。
  - 冲击 × 重甲：同一单位两词条同时存在时（本卡池没有；夹具验证）——首次攻击免反击（重甲无处可用），
    第二次攻击（若恢复攻击机会）反击照常、重甲照减——两条款互不干扰。
  - 冲击 × 伏击：官方"冲击无视伏击"——**伏击本轮不做**（任务 5），届时在伏击的结算里处理"冲击抵消任何反击伤害"，本轮仅登记。
- **实现**：`CounterDamage` **第一行**（冲击 ⇒ 0，覆盖全部兵种条款）；消耗在 `AttackWithUnit`
  成功路径（`if (attacker.HasShock) attacker.HasShock = false;`——**只要攻击就消耗**）。
  ⚠️ **`CounterDamage` 必须保持纯函数**（无副作用）——`PreviewAttack` 会调用它，**预览绝对不能消耗冲击**。

## 3. 九问九答

### Q1 数据怎么存？为什么不用 string[] / List<string>？

**方案**：`CardDef` 加两个字段（伴一个新的 flags 枚举）：

```csharp
[Flags]
public enum Keyword
{
    None  = 0,
    Blitz = 1 << 0,   // 闪击
    Shock = 1 << 1,   // 冲击
    // 第二批（烟幕/守护/伏击）与第三批（奋战）在各自轮次追加枚举值，本轮不加。
}

// CardDef 新字段（readonly，构造注入）：
public readonly Keyword Keywords;      // 布尔型词条（位掩码）
public readonly int     HeavyArmor;    // 数值型词条：重甲 X（0 = 无；1~3）

public bool HasKeyword(Keyword k) { return (Keywords & k) != 0; }
```

**为什么不用 `string[]` / `List<string>`**（四条，全部有项目内先例）：

1. **编译期检查**：字符串拼错（`"blitz "` 多个空格）**静默失效**——本项目把"静默错误"列为头号敌人
   （F2 精准打击归属、F6 召唤失调都是"两套语义但没人报错"）；枚举拼错**编译不过**。
2. **不可变性**：`CardDef` 的现有字段**全部 readonly**（构造后不可变，运行时零改写）；
   `List<string>` 是引用类型，构造后仍可 `Add`——要防共享可变就得包装，不如位掩码干净。
3. **判定成本与语义**：`(def.Keywords & Keyword.Blitz) != 0` 是 O(1) 位运算；
   字符串要 `Contains` + 大小写/中英文歧义（"闪击"还是 "Blitz"？）。
4. **与现有风格一致**：`CardType` / `UnitType` / `EffectId` 全是枚举——词条没有理由换个物种。

**为什么重甲不塞进 flags**：它是**带等级**的数值（1/2/3 直接参与减法），位掩码表达等级要靠 3 个位硬编码，
又丑又容易错。"是否拥有重甲" 的唯一真相 = `HeavyArmor > 0`（单一来源，不需要冗余的 flags 位）。

**为什么不用"改 Def 实现一次性状态"**：`CardDef` 是不可变的共享卡定义——若把"冲击是否已用掉"写在 Def 上，
**同一张卡的所有实例 + 下一局游戏全部被污染**。一次性状态必须放 `UnitInstance`（见 Q3）。

### Q2 重甲的唯一合法挂载点在哪？两处扣血语句的区别？

**代码核实（已找到全部三个扣血点）**：

| 位置 | 语句 | 通道 | 重甲是否作用 |
|---|---|---|---|
| `Combat.cs:362` | `attacker.Health -= damageToAttacker;` | **单位攻击·反击侧** | ✅ **作用**（减 attacker 的重甲） |
| `Combat.cs:363` | `target.Health -= damageToTarget;` | **单位攻击·主动侧** | ✅ **作用**（减 target 的重甲） |
| `Combat.cs:448` | `u.Health -= amount;`（`DamageUnit`） | **指令卡 / AOE / 疲劳共用** | ❌ **绝不作用** |

**挂错会出什么问题**（两个方向都错）：
- 若挂进 `DamageUnit`：精准打击 / 炮火覆盖 打重甲单位会"打折"——违反官方"重甲不减指令伤害"，
  且**静默**：200 局里表现为"指令卡效果莫名变弱"，与词条强度混在一起，**无法归因**；
- 若两行里只挂一处（如漏了反击侧）：反击伤害照旧——"重甲单位互换时更耐揍"这半个效果只在
  被攻击方向生效，玩家/数据两边都说不通。

**实现收口**（两行都要走"唯一出口"，禁止内联减法）：

```csharp
// Combat.cs 新增（与 CounterDamage 相邻）：
/// [任务4] 单位攻击的主动伤害：攻击力 − 目标重甲（下限 0）。
/// "重甲只减单位攻击伤害"的两个作用点之一；另一个是 CounterDamage 的收尾。
internal static int UnitAttackDamage(UnitInstance attacker, UnitInstance target)
{
    if (attacker == null || target == null) return 0;
    int raw = attacker.Attack;
    int armor = target.Def.HeavyArmor;
    return raw > armor ? raw - armor : 0;
}
```

`AttackWithUnit` 与 `PreviewAttack` **两处同步改走它**（漏一处 = 预览与结算两套语义——本项目已踩两次）。

### Q3 冲击与"火炮自带免反击"如何共存？一次性状态存在哪、何时清除？

**统一到 `CounterDamage` 一个出口**（现有结构：四判兵种条款 ⇒ 改为五判，冲击放**最前**）：

```csharp
internal static int CounterDamage(UnitInstance attacker, UnitInstance target)
{
    if (attacker == null || target == null) return 0;

    // ⓪ [任务4] 冲击：首次攻击抵消敌人的反击（"任何"反击伤害 ⇒ 覆盖全部兵种条款）。
    //    ⚠️ 必须保持纯函数——消耗在 AttackWithUnit，PreviewAttack 只读不消耗。
    if (attacker.HasShock) return 0;

    // ①~④ 兵种条款：原样保留（轰炸机当防守方 / 轰炸机当攻击者 / 火炮 / 常规）——顺序不动。
    int raw = ...;

    // ⑤ [任务4] 重甲：受击方（此处为攻击者）受到的"单位攻击"伤害 −X（下限 0）。
    int armor = attacker.Def.HeavyArmor;
    return raw > armor ? raw - armor : 0;
}
```

**一次性状态**：`UnitInstance` 新增实例字段

```csharp
/// [任务4] 冲击"当前是否还没用掉"。构造时从 Def.Keywords 初始化；
/// 用掉后置 false，**不随回合恢复**（官方口径：不自动刷新）。Def 保持不可变。
public bool HasShock;
// 构造：HasShock = (def.Keywords & Keyword.Shock) != 0;
```

**清除时机（唯一消耗点）**：`AttackWithUnit` 成功结算路径（与 `SpendAttack` 相邻的"本次攻击已发生"记账区）：

```csharp
if (attacker.HasShock) attacker.HasShock = false;   // 只要攻击就消耗（本作拍板：不采用"打 HQ 不移除"的官方细则）
```

**为什么消耗不放 `CounterDamage` 里**：`PreviewAttack` 也调 `CounterDamage`——
若在那里消耗，**玩家每次把鼠标悬停到敌人身上就会烧掉冲击**（预览即消耗），这是灾难级 bug，
且在校验里完全静默。纯函数 + 显式消耗点 = 唯一安全结构。

### Q4 闪击的实现点？与坦克"移动+攻击"（任务 3 已做）如何咬合？

**是**——唯一实现点就是部署时的 `DeployedThisTurn`（`Play.cs:138`）：

```csharp
// 旧：unit.DeployedThisTurn = true;
// 新：
unit.DeployedThisTurn = !card.HasKeyword(Keyword.Blitz);   // 闪击跳过部署失调
```

**与坦克行动经济的咬合 = 零特殊代码**（本次核实的新细则①反而证明了这一点）：
- 闪击只负责"解除失调"；解除之后，**行动额度完全由任务 3 的既有出口判定**：
  `CanUnitMove/CanUnitAttack` ⇒ `HasMovedThisTurn / HasAttackedThisTurn`（坦克=各一次、其余=任一即止）；
- 于是官方那两句细则**自动成立**：
  - 闪击 × 非坦克 = 登场当回合"移动 **或** 攻击"（二选一，因为非坦克的 `HasNoActionLeft` 是 OR）；
  - 闪击 × 坦克 = 登场当回合"移动 **且** 攻击"（坦克的 `HasNoActionLeft` 是 AND）。
- ⚠️ 本卡池**当前没有"闪击坦克"卡**（挂载见 Q6）——组合语义由"闪击真实部署路径"（第 12 项）
  与"非失调坦克可移+攻"（第 11 项既有断言）**两截复合覆盖**；若后续某轮给坦克卡挂闪击，再补端到端断言。
- 「视作坦克 / 能在同一回合中移动并攻击」的特例卡条款：**登记不实现**（本作没有此类卡面文字系统）。

### Q5 面板预算怎么办？（已拍板 (a) 面板折让，本步给出实现方案）

**`ValidatePanelBudget` 公式扩展**（`CardDb.cs:207`）：

```csharp
// 旧：int expected = CardDef.BudgetForCost(c.Cost);             // 2 × 费用 + 1
// 新：
int expected = CardDef.BudgetForCost(c.Cost) - (HasAnyKeyword(c) ? 1 : 0);   // 带词条 ⇒ −1
```

- `HasAnyKeyword(c)` = `c.Keywords != Keyword.None || c.HeavyArmor > 0`（"有词条就 −1"，**不论几条**、不论大小）；
- 同时新增三条数据校验（进 `ValidatePanelBudget`，由自检第 1 项兜底）：
  ① 单位卡 `HeavyArmor` ∈ [0, 3]（官方"最多 3 重甲"）；
  ② `Keywords` 只允许 `None | Blitz | Shock`（未实现位被填 ⇒ 报错——防"加了枚举值忘了实现"静默上线）；

### Q6 第一批把三个词条分别挂到哪些卡上？（逐卡对照表）

**筛选原则**（四条）：
1. 每种词条至少 1 张卡（否则 200 局采样不到，白改）；
2. 兵种 / 风味贴切（空降 → 闪击；装甲 → 重甲；远程狙杀 → 冲击）；
3. 折让后**不破坏卡的原定位**（拆分方向统一"保攻降血"，见下）；
4. 首轮**不做一卡多词条**（避免"哪条词条产生了效果"无法归因）。

**对照表（6 张；全部满足 `面板 = 2 × 费用 + 1 − 1`）**：

|---|---|---|---|---|---|---|
| 伞兵 | 3 | 3/4 | 2 | **闪击** | **3/3** | 空降兵 = 快速部署的直接风味；3 费中期牌 |
| 战斗机 | 3 | 4/3 | 2 | **闪击** | **4/2** | 制空快速反应；越线兵种——闪击让它"上线当回合即可越线打击" |

  重坦的 7 攻打脸）不漂移，200 局里"卡池变强/变弱"的可归因面最小；
- ⚠️ 副产物（要如实写进文档）：对"单位攻击"的**一击阈值**，`血−1 + 重甲 1` 与原来基本等价
  （例：装甲车从"5 血需 5 攻才能一击清除"变为"4 血 + 重甲 1 ⇒ 需 5 攻"——阈值不变）；
  但**逐刀伤害**会变（1 攻单位对重甲 1 **完全免疫** = 0 伤；2 攻单位更肉）——**这是重甲的词条强度本体**，不是 bug。

### Q7 GreedyAI 需要改哪几处？（防"AI 不改 = 新机制测不出"）

**只需 2 处**（其余全部自动跟上——这是"收口设计"的红利）：

1. **`PlayCardsPhase` 的 reserve 重算**：现注释写着"新部署的单位处于部署失调，本来就不能行动，所以算一次就够"——
   **闪击打破了这个前提**（新部署的闪击单位当回合就能行动）。改法：把 `ReserveForActions()` 从
   "出牌循环前算一次" 挪到"**循环内每次重算**"（一行挪位）。闪击单位部署后 `DeployedThisTurn=false`，
   自动进入"待行动"计数，AI 会自动给它留行动费——**零新逻辑，只是让引擎的事实即时可见**。
2. **`AttackPhase` 的 kills 判定**：`bool kills = atk.Attack >= tgt.Health;` ⇒
   `bool kills = GameEngine.UnitAttackDamage(atk, tgt) >= tgt.Health;`（重甲会吃掉伤害，自己算会高估击杀——
   任务 D 同款教训："AI 自己猜"必然与引擎漂移）。

**自动跟上的部分（不用改，但要写进验收核对）**：
- `dies = GameEngine.CounterDamage(atk, tgt) >= atk.Health`——`CounterDamage` 已含冲击（0）与重甲（−X），
  **AI 自动知道"有冲击的单位首攻不会死""有重甲的单位挨得更少"**；
- 闪击单位的行动采样：攻击/移动阶段都扫全单位 + `CanUnitAttack/CanUnitMove` 判定，
  闪击单位部署后**自动进入候选集**（不需要"AI 知道闪击"）；
- 坦克冲锋收尾（`TankChargePhase`）：闪击坦克（本卡池没有）若将来存在，自动被它捡到"移过没攻"的收尾。
- **不改的**（登记理由）：`MovePhase` 的单位评分（`Health * 2 + Attack`）不感知重甲——这是"目标价值近似"，
  重甲只改伤害不改价值排序；`IsWorthPlaying`（指令卡）完全不涉及伤害公式，**不需要**动。
